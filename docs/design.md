# Design

How Clean looks and moves, decided in one place (2026-10-08) so that screens stop choosing for
themselves. The rules are held in code in `app/.../ui/theme/` and `app/.../Ui.kt`; a new screen is
built from those pieces and types no colour, corner or button style of its own.

## Rules

| | Decision | Where |
|---|---|---|
| Colour | Black or dark base with three neutral steps above it. **One accent**, for the main action on a page, the current selection, and names that lead somewhere. The theme's secondary slots are filled from the accent, so nothing falls back to Material's purple. | `Theme.kt` |
| Meaning colours | Done and PR green, warm-up amber, failure red, drop purple, danger red. Named once, in both themes. | `CleanColors`, read through `LocalCleanColors` |
| Shape | Three corners only: 8 dp (number boxes, chips, badges), 18 dp (cards, buttons, bands), 24 dp (sheets, dialogs, the tab bar). What is docked to the bottom edge has the same corner on its top only. | `SmallShape`, `CardShape`, `SheetShape`, `CardTopShape`, `SheetTopShape` |
| Space | A 4 / 8 / 12 / 16 / 24 grid. A card's padding and line gaps scale with the text size from Settings. | `Section` in `Common.kt` |
| Type | Material's scale times the text-size setting; `bodySmall`, `labelMedium` and `labelSmall` are never under 11 sp, Material's floor (2026-10-14). Digits are fixed-width everywhere, so clocks and columns do not shift. Headings over columns are small spaced capitals, always muted. | `Type.kt`, `Caption` |
| Words | Sentence case on buttons ("Add set", "Finish"), not capitals. | |
| Motion | Short and physical, and every duration, curve and spring has a name; a screen types no number of its own (see "Motion vocabulary"). Nothing decorative. Settings, Appearance, Animations turns it all off. | `Motion.kt`, `LocalMotion` |
| Touch | A short buzz when a set is ticked, when a swipe passes the point of removing, and when an exercise is picked up to drag. | |

Exceptions: the tiny legend squares keep a 3 dp corner, and the colour tables that are data
(calendar palettes, BMI bands, fatigue colours, sticky-note colours, chart series) stay where
they are.

## Pieces (`Ui.kt`)

- `MainButton`: filled accent. The one thing a page is for; at most one per page.
- `QuietButton`: dark tint, accent words. Every other button. Both take an optional `summary`, a smaller line under the words saying what the button does (the "Update template?" options, 2026-10-12: stacked full width, the first update on offer being the `MainButton`).
- `DangerButton`: red words, no fill. Anything that throws work away.
- `Badge`: a small tag, green by default (PRs).
- `Caption`: the muted capitals over a column or on a tile.
- `EmptyState`: what a list says when it is empty, with the way to fill it.
- `Section(onClick = …)`: a card pressed as a whole; it dips and the ripple keeps to its corners.
- `Modifier.pressable`: the dip, for tiles and boxes. Plain rows keep `clickable`.
- `SwipeRow` (Ui.kt; `SwipeToRemove` is its left-only form): a row with an action per direction, each an icon and a word on its meaning colour (done for finish, danger for remove; icon and word keep it Mono-safe) that opens behind the row, turns solid past the threshold with the buzz, and is offered to a screen reader as a custom action. In a workout (`SetSwipe` in `Active.kt`, 2026-10-16) a set row swipes right to finish and left to delete by default (Settings, Workout, Layout: kv `swipe.right` / `swipe.left`, each finish / delete / off). Finish is the box's own tick (hints accepted, rest started, PRs judged) and the row springs back; on a done set it un-ticks, as the checkbox does (word "Not done"). The threshold buzz is the tick's (`feedback.tick`). A left and right round swipes as one row but acts on one half at a time: the first half not done, and once both are done the right half is un-ticked. An exercise's name row (2026-10-21, the user's words) swipes to remove the whole exercise, with the "Exercise removed" Undo, in each direction whose set swipe is delete (left by default; a direction set to finish or off does nothing on the name, `removesExercise`); there is no swipe on the name in focus mode, where a sideways swipe turns the page. While the cards are folded for reordering the swipe stays in place but does nothing (the hold owns the finger): taking its detector away mid-hold ended the hold, which broke reordering (2026-10-21, `ReorderHoldTest`). Earlier text: `SwipeToRemove`: swipe left; red opens behind the row, turns solid past the threshold, springs
  back short of it. Sets in a workout, exercises in the template editor.
- `Sheet`, `SheetRow`, `SheetGap`: menus rise from the bottom, each row with an icon and its
  current value; a row that deletes is red and last. Yes/no questions stay as dialogs.
- `drawnIn`: a chart's line draws in once from the left.
- Left and right on a chart (stage 5; `SplitLineChart`, `ChartPoint`, `SplitMarks` in `Stats.kt`; points built by
  `chartPoints` in core from `progressBySide`). A chart is one series per measure that mixes both kinds of session:
  a session done left and right is one x position with two markers joined by a stem (left a filled circle, right a
  ring, so it reads without colour; the stem is the line's own colour at 0.2 alpha), and equal sides are one marker
  with a ring around it. There are two lines, not one (the user's wish): the left markers are on a solid line and the
  right markers on a dashed one (the chart's stroke width, 6 dp on, 4 dp off), each running through every session, an
  ordinary session giving both its single value so the two run together there. In "All" each measure keeps its colour
  for both lines. An ordinary session is one marker with no
  stem (a small dot, drawn only on a chart that has a stem, so charts of ordinary work are as they always were). The
  axis takes in both ends of every stem. A key, a short solid line with a filled dot, "Left", and a short dashed line with a ring, "Right"
  (drawn on a canvas in the line's colour, the neutral text colour in "All"), appears under a chart only while one
  is in view (one for the whole "All" chart, which keeps each measure's own line colour and scale). A tap anywhere
  on the session's column opens a card with `L 100 kg · R 92 kg`, the date and the workout. Stems and markers are
  built once in `drawWithCache` into a path and flat arrays; drawing them allocates nothing.
- The imbalance chart (Charts tab, only when a session has both sides): right minus left, in percent of the larger side,
  one point per paired session by the first of estimated 1RM, reps, volume that any has (`imbalanceSeries`), not part
  of "All". The zero line is the axis; "Above 0: right leads. Below 0: left leads." is written under it, the tap card
  says `Right leads by 8 %`, and full screen keeps all of it (`ChartSeries.imbalance`).
- Left and right on the body figure (stage 6, 2026-10-12). Every outline that lies on one side of the body has a side
  (`BodyPart.side`, the person's own: in the front view the figure's right is on the viewer's left, in the back view the
  viewer's left is the figure's left; null across the midline, which is the neck's centre outline and the head). `BodyFigure`
  takes `sideColours` and `headSideColours` and shades a limb from them where it has an entry, else as before; a tap on such a
  limb names the side ("Left biceps", then the number or word for that side) and opens the page as it did. The Body page's
  fourth chip, **Sides**, is there only while the time frame has left and right work (`hasSideWork`; a remembered "Sides" falls
  back to Balance without it). It shades each limb by its own side's sets with Balance's palette and square-root rule, one
  scale across both sides so a difference shows; its rows are `Biceps  L 24 · R 18` with two thin bars (each in its side's
  colour on the figure) and a quiet `(R −25 %)` under, the largest gap first; above them one line, "Biggest gap: right biceps
  −25 %", opens that muscle. A row opens in place into its heads with `L · R` numbers and two bars each, and the open group's
  heads are drawn per side. Fatigue and Strength shade each limb by its own side, with the rows' quiet `L fatigued · R ready`
  caption only where the sides differ. The caption of the Sides view says what the gap is: the lagging side below the larger
  one, in % of the larger. The figure's spoken description in the Sides view is "Body figure, sides: largest gap right
  biceps, 25 percent less", each row one sentence ("Biceps, left 24 sets, right 18 sets, right 25 percent less").
  A muscle's page follows the view the Body page is on: in Sides its two limbs are shaded by side; in Fatigue and Strength
  they are coloured by side only when the sides differ (else the page's one tint as before). Its "Left and right" section
  (only with left and right work in the frame) has the counts, the gap, "Sets per week, left and right" (`MultiLineChart`
  with `shared`: two lines, the accent and the tertiary colour, one scale) and "Open exercises". A head's page has the same
  section and its own two limbs.
- The number pad (`Keypad` in `Active.kt`): weights and reps are typed on the app's own pad, not
  the phone's keyboard. Five columns since round 11 (2026-10-18), every key its own and at least 48 dp: the digits in three, then a
  column of the step down and up (the exercise's weight step, or one rep) and RPE (an empty place when RPE is off), then Next (the main
  key, top right; it walks weight, reps, next set), Same and Delete; the bottom row is the close key under 7, `0` under 8 and `.` under 9, its last two columns
  empty (2026-10-21, the user's words). RPE opens a two-row scale above the keys (6 to 8, then 8.5 to 10).
  Every way the pad goes away (the key, Back, the phone's keyboard coming up, Next past the last box) is `Pad.close()`: no
  box is left focused or in edit mode, and what was typed stays (2026-10-16). Ticking a set does not close it. The first
  digit typed in a box replaces what was there. It replaced step buttons under the next set,
  which the user disliked. A "Same" key (2026-10-16) copies the value of the
  same box from the set above into the focused box (`setAbove` in core: the previous set; in a left and right card the same
  side of the previous round, else for a right half the left half of its own round). It is dimmed when there is no set
  above or its box is empty. Like a step, the next digit starts afresh.
  Left and right (2026-10-16): when the same side of the round above has nothing in that box, the key takes the other side's (`setsAbove`).
  Last time's values carry across the two ways of logging (`carriedSets`, `docs/domain.md`, Left and right: carrying values over):
  an ordinary card reads a left and right session as one set per round (the heavier side's), a left and right card gives both
  halves of round k an ordinary session's set k. The grey hint, the Previous column and what a tick accepts all come from that one list.
- Ticking accepts the hints (2026-10-16): ticking a set (the box, a half of a pair, or the focus header's Done) first fills
  each empty box with exactly the grey hint it shows (last time, the template's target or the progression target, one
  value per box computed once in `viewOf` and used for both display and ticking; `acceptHints` in core), then ticks as for a
  typed set. A typed box keeps its value. With no usable reps/seconds/minutes (typed or hinted) the set is not ticked and
  the usual "Enter the reps first" shows. Unticking leaves the filled values, as for a typed set. The "Finish workout?"
  rule is unchanged: a hint is not a value for an unticked set.
- `CleanIcons.kt`: the few icons beyond Compose's basic set (Material icons, Apache 2.0, see
  `NOTICE.md`).

## Card corners (2026-10-19)
A card's corner is the look's (`Look.corner`: 18 dp, 26 in Linen). Every card, tile, band, the held card in a workout, the animation box, a Settings row's icon box, the workout banner and a finished workout's totals read it through `cardShape()`, `cardCorner()` or `cardTopShape()` (`Theme.kt`); the 18 dp shape itself is private to the theme. `OneLookTest` fails on a corner of 12 dp or more typed in a screen.

## Spacing steps (2026-10-19)
Paddings, gaps in a row or column, spacers and `Section`'s `spacing`, `inner` and `outer` take a step of `Space` (`Space.kt`): `xxs` 2, `xs` 4, `s` 8, `m` 12, `l` 16, `xl` 20, `xxl` 24, `xxxl` 32 dp. When the steps came in, the numbers between were moved to the nearest step, a tie to the more used one: 3 and 5 to 4, 6, 9 and 10 to 8, 14 and 18 to 16, 22 to 24, 28 to 32 (so a card's gap between lines is 8, not 10, and its margin above and below 8, not 6). Sizes (a box, a chart's height, the room for the tab bar) and hairlines of 1 dp keep their numbers. `OneLookTest` fails on a number from 2 to 32 dp typed in a padding, gap or spacer.

## Light looks: chart lines and sticky notes (2026-10-19)
On a light page (Light, Linen) the lines of a chart with several (`seriesColorsOf` in `Stats.kt`) are the same four hues deepened (`#2B62C4`, `#946200`, `#0B7D60`, `#C2306E`), each at least 3:1 against the page, the cards and white; the dark looks keep the pale ones. A sticky note's named colours have pale twins on a light page (`STICKY_COLORS_LIGHT`, `stickyBand` in `Common.kt`), so the band reads as a note with dark text; a colour the user picked on the wheel is kept as picked on both. Settings' swatches show the band the page will draw. `LightColoursTest` checks both.

## Type scale (2026-10-16)
The one scale is Material 3's, in `ui/theme/Type.kt` (times the text size setting; `bodySmall`, `labelMedium` and `labelSmall` never under 11 sp). A screen picks a role from this table and types no size of its own.

| Used for | Role |
| --- | --- |
| Page title (the big heading of a tab) | `headlineLarge`, bold |
| Section title: a heading over a group on a tab or page, and a card's title (Statistics, History, Body, Activity, Quick start, Templates, a month on the calendar) | `titleMedium`, bold, always through `SectionTitle` (`Common.kt`; read out as a heading, guarded by `OneLookTest`) |
| Sheet title | `titleLarge`, bold |
| Name of a thing on an editor page (a template or a day in the Program editor) | `headlineSmall`, bold |
| Card value, the number a tile leads with | `headlineMedium` with `numbers()`, semibold |
| Hero numbers (the weight on the ruler and in Welcome, a set's weight in focus mode, the rest countdown) | `displaySmall` to `displayLarge` with `numbers()` |
| Row label in a list or Settings row | `bodyLarge` (the default `Text`) |
| Dense row: a link row with its value at the right (`NavRow`), the rows inside Progress's History card | `bodyMedium`, value muted |
| Caption under or beside a value, hints, a card's quiet value | `bodySmall`, muted |
| Small capitals over a group (`Caption`) | `labelSmall`, semibold, spaced |
| Chip, button, tab label, badge | `labelLarge` (buttons), `labelMedium` (chips, badges, tab labels) |

Deliberate exceptions, all scaled by the text size setting: the letter rail on the Exercises tab (10 sp) and the labels drawn inside charts and the activity grid (10 to 13 sp, drawn on a canvas, which cannot use a text style); numbers set in Plex Mono through `numbers()` keep their role's size. A card or row that wants something else asks for a new role here first.

## Statistics card (2026-10-16)

Progress's Statistics card (`StatisticsCard` in `Progress.kt`, rules in `core/StatsPeriod.kt`, tested in `StatsPeriodTest`), top to bottom: the title; a period choice Week / Month / Year / All (`Choice`, kept as kv `ui.stats.period`, default Month); four `Tile`s in a 2 x 2 grid (Workouts, Volume, Time trained, Sets; the card-value role, `headlineMedium` with `numbers()`); a quiet caption; a volume bar chart; "Most trained muscle" and "Top exercise" lines; the old `NavRow`s (Trends, Personal bests, Trophies, Calendar, Measurements, BMI) compact at the foot.

- **Periods.** Week is this Monday to today, Month the first of this month to today, Year 1 January to today, All the first workout's day to today. Nothing counts after today.
- **Compared like for like.** Each period is set against the same elapsed days of the one before (Oct 1 to 16 against Sep 1 to 16; Monday to Wednesday against last Monday to Wednesday). A shorter earlier period ends with its own last day (Mar 31 against all of February). The caption under the tiles says so ("vs the same days last month"). All has no change line and no caption.
- **Change format.** A tile's second line is the change and the earlier period's name: Workouts and Sets in absolute numbers ("+3 vs last month"; halves are possible with left and right), Volume and Time trained in percent ("+12 % vs last month"). Equal (or a percent that rounds to nothing) reads "same"; a rise from nothing reads "new". Direction is the sign, never a colour, so it reads the same in Mono.
- **Chart.** 80 dp of bars of volume lifted (`model.volume`, profile unit): Week the 7 days Monday to Sunday, Month every day of the month, Year the 12 months, All by month (by year past 24 months). The bar holding today is the accent, past bars a quieter tone of it, empty or coming ones a faint stub. Under it, the names of the first and last bar; the chart is one spoken sentence. Drawn in `drawWithCache`; the figures are worked out once per workouts / period in a `remember`.
- **Lines.** The muscle with most working sets (`muscleSets`, so the user's muscle settings apply) opens its page; the exercise with most working sets opens the exercise. A period with no workouts shows its zeros and "No workouts in this period" in place of the chart and lines.

## Softer cards, the tab bar, the Home header and the ruler (2026-10-12)

Light and fast: solid colours only, no blur, no shadow or elevation, no gradient, nothing that animates by itself.

- **Cards.** A `Section` is a very faint fill one step above the page (`surfaceContainer` at 55%) with an outline at 60% of the usual, and the card corner is 18 dp (it was 14). A tile (`Tile`) keeps the full `surfaceContainer`, so it still reads inside a card. All colours are the theme's, so the light theme and the dark-grey background follow. `Section(hero = true)` is the one washed with the accent (10% fill, 35% outline): Home's Today card and nothing else.
- **Tab bar** (`TabBar` in `MainActivity.kt`). A 68 dp bar (64 until 2026-10-16) in `surfaceContainer` with the theme's outline, floating 8 dp above the bottom edge (plus the navigation bar) with 16 dp at the sides, corners 24 dp. Since 2026-10-15 (the user: "I don't like the asymmetry, I want the name below the icons") the bar is Material 3's navigation bar layout: five slots of equal width, each an icon in a 56 x 32 dp pill with its word centred under it in a line that is always kept, so no icon ever moves; the selected tab's pill is filled (the accent container) and its word bold (which tabs show words, and their order, are choices: see "Tab names, tab order and the middle tab"). Workout, in the middle slot, has a larger pill (68 x 38 dp with a 28 dp play icon since 2026-10-16, round 7: "make the middle workouts button bigger"; the bar grew 4 dp so it still has room), always filled with the accent, with the word Workout under it on the same line as the other words (its pill rises 12 dp instead of 10 when the word shows, so its bottom edge stays clear of the word); with a workout running it is spoken "Resume workout" and a tap goes into the workout (the banner above it has the clock). A swipe between tabs still works (the `HorizontalPager`). The "workout in progress" banner, when its Settings scope shows it, is docked on top of the bar inside the same surface (so it takes the bar's corners) and the Everywhere overlay on pages behind the tabs is as before. The keyboard covers the bar, as it covered the old one.
- **Settling.** Every tab's list reports whether it is scrolled to its end (`BarEnd(tab, listState)`, `LocalBarEnds`). At the end the bar loses its side margins and every one of its corners (it is square, the docked banner too) and lies on the bottom edge, filling the navigation-bar area (160 ms, instant with animations off), the way a finished workout's `Total` bar settles; scrolling back up lifts it. The room a list leaves for it (`BarSpace`, `LocalBarInset` = bar + gap + navigation bar + the banner when shown) is the same floating or settled, so settling never changes what can be scrolled. A new tab page ends its list with `item { BarSpace() }`, calls `BarEnd`, and keeps a drag-only rail (the letters) clear of the inset.
- **Home header.** "Today" in small muted words over the date as the title in the phone's own order (`DateFormat.getBestDateTimePattern`, "Monday, 12 October"); at the right a chip with the week streak number (a star, and a shield while one is held) that opens Trophies. Then the cards the user chose.
- **Today hero.** The Today card is the page's one main button: "Start workout" (the program's slot, else the Current split's next template, else an empty workout), and while a workout runs the card is that workout ("In progress", its name, "Resume workout"). On a rest day or a day already done it names the day and what is next and the button starts that next template anyway. "Not this one" stays quiet beside it and goes while a workout runs.
- **Week marks.** Under "This week"'s ring, seven round marks Monday to Sunday: the accent filled for a day trained (it opens that day's workout, or the calendar's page of the day when there were several), a ring for today, plain for the rest, dimmer for days to come. Each is spoken ("Monday 12 October, trained").
- **Weight ruler** (`WeightSheet` in `WeightRuler.kt`). Logging a body weight (the Weight tile with no entry, the weight page's "Log weight", the workout and summary nudges: `AppModel.logWeight()`) rises as a `Sheet`: the value as a big number with its unit (tap to type it), a horizontal ruler under it, "Date" (today, or the phone's pickers) and Save, the sheet's one main button. The ruler is one `Canvas` drawn from the scroll position: ticks every 0.1, longer every 0.5, a label at each whole number, a fixed accent marker in the centre; it flings and settles on a tenth, with a short vibration per tenth only when animations are on. It opens at the last weigh-in (70 kg or 155 lb with none). For a screen reader it is a slider with the value and "Increase by 0.1" / "Decrease by 0.1". The entry is stored in kg and written as every weigh-in is.

## Tiles, lines and the Exercises toggle (2026-10-13)

- **Sparklines.** A `Tile` whose page is a chart can show that chart on itself: `Tile(spark = ...)` draws `Sparkline`, a 2 dp accent line (80%) of the last 26 weeks, oldest first, 28 dp tall under the number, with no axes, numbers or dots, built once in `drawWithCache`. It is decoration: a screen reader skips it and reads the tile as before. Workouts, Time trained and Volume lifted are per week (`recentWeeks`, from `AppModel.weekTotals`, worked out off the main thread); Week streak is the run's length after each week (`Streak.runAfter`: it climbs while the target is met and falls to nothing on a miss); Weight is the weigh-ins; PRs, 30 days is PRs a week over 12 weeks. A tile with no chart behind it (This month) has none. Home's "At a glance" and the Profile tab share the component.
- **Quick action on a tile.** `Tile(onAdd, addLabel)` puts a "+" (a 32 dp circle in a 48 dp touch area, spoken by `addLabel`) at the right; the Weight tile's opens `WeightSheet` on the page you are on, and the rest of the tile still opens the weight page.
- **Smooth lines.** Every chart line is a monotone cubic curve (`monotoneSlopes` in core, `Path.curveThrough` in `Stats.kt`, the one place a line's path is built): through every point, never above or below the two it runs between, so no overshoot and no dip that is not in the data. Two points are straight, one is a dot, two points on one day make a step. It applies to `SplitLineChart` (and so `LineChart`, the weight chart, Trends and the full screen, with the dashed right-side line), `MultiLineChart` and the sparklines; markers, stems, goal and zero lines, bands and the fitted trend line stay straight.
- **Exercises: All / Performed.** Two chips at the top of the Exercises tab's list (kv `exercises.show`, `all` or `performed`, default `all`). Performed keeps the exercises with at least one logged session in this profile; it works together with search, favourites, the equipment and muscle filters. The "hide built-in exercises until searched for" option (`library.hide`) is a second way of the same kind and is left as it is: with All it behaves as before, with Performed its note is not shown (nothing is hidden that Performed has not already left out). The picker inside a workout does not show the chips.

## Screens

- Pages slide in a little from the right and back out, in 160 ms, and are solid after 80; the
  workout rises from the bottom and drops back; tabs switch at once and keep their scroll position
  (`MainActivity.kt`). Longer, softer transitions were tried first and read as the app being slow.
- Workout: Finish is the filled button; Add set and Add exercise are quiet; a ticked row is tinted
  green and its box bounces; the rest drains as a line under the top bar and along the "workout
  in progress" bar; a superset is a line down the left of its cards.
  - Moves (2026-11-16): the next-set highlight glides from row to row, a done tint spreads from the tick, a finished exercise folds up into its line and unfolds, a removed set closes its gap and Undo opens it, and a set's "Change type" grows from its number into a centred dialog with the set left lit; see "Motion vocabulary". The full calendar ends at today (no later day is drawn).
- Left and right, which side went first (2026-10-13): a finished round that was done right first (`Round.rightFirst`) shows a small muted "1st" after its right value in `RoundRow` (workout page, summary, the exercise's History tab), nothing on rounds that went left first, and its spoken text ends "right first"; no setting, no column. The logging screen has no mark. In a card, ticking a half in a later round while the round directly before it has exactly one half ticked ticks that other half too (the same values an empty box takes from its hint, one tick after the half already done), with an "Other side ticked too" Undo in the bottom bar; it does nothing when the earlier round has no half ticked, when the card is another, or when the missing half has no reps to take.
- Left and right, stage 3 (2026-10-12): a card carries its own paired flag; a round's badges are one row under the round ("1RM L", "Reps R", "Weight L R"), each half is judged and hinted against its own side, and a finished workout's exercise has a small options button with "Read as left and right" / "Read as ordinary sets" (Undo offered).
- Left and right, stage 4a (2026-10-12): a finished paired block is drawn as its rounds (`RoundRow` in `Workouts.kt`, shared by the workout page and the summary). Under a small L and R head (`RoundHeads`, a `Caption` over each column) a round is one row in the ordinary set row's type: the number or kind letter in 36 dp, then the left set and the right set in equal columns, a half not done as a muted dash. The round's badges are one row under it, indented like a set's ("1RM L", "Reps L R", matched in the matched colour), and tap through to the exercise. When the sides differ, a small muted caption sits on the block header in place of the "1RM" head ("Right -2 reps" when reps decide, "Left -7 %" otherwise); equal sides show nothing. Each round ends with the two sides' estimated 1RM in two narrow right-aligned columns headed "L 1RM" and "R 1RM" (asked for by the user, 2026-10-15), where an ordinary set has its one 1RM: on the workout page and the exercise page's History tab, not on the summary. A round reads as one line to a screen reader ("Set 2, left 20 kilograms 12 reps, right 20 kilograms 10 reps"). History's card shows the best round on one line, the letters quiet, wrapping to two lines at most. Since 2026-11-02 (the user's words: "the 1RM should show up in the history of workouts") every other exercise on History's card has its best estimated 1RM by the chosen formula (warm-ups and drop sets left out, to a tenth) in a narrow right-aligned column headed "1RM", or under "R 1RM" when the card also holds a left and right exercise; a finished workout's page already gives each set's 1RM. A count of sets or PRs may end in a half and is written "2.5", "1".
- Left and right, stage 4b (2026-10-12): the exercise page. PRs tab: a row shows the comparable figure (the weaker side's) as before; for an exercise with left and right history a quiet `bodySmall` line under it gives `L` and `R` each with its own figure, each opening its workout; the reps-at-weight and longest-hold tables carry a quiet `L 12 · R 10` under a weight. History tab: a paired block is its rounds (`RoundRows`) with the lagging side as a caption under them, an ordinary block as before. Info tab: "Imbalance" (latest gap, `Right −2 reps · −17 %` or `Even`, opens the History tab at that workout) and "Rounds logged" under the "Left and right" line, shown only with paired history. Personal bests: a quiet `L 100 · R 92` under a best lift; PR rows say `L` or `R`. Muscle and head pages: `Left 24 · Right 18` under "Sets", and an exercise reads `6 sets as 3 × ½` where a round counted as one. ## Accessibility (2026-10-12)

Rules now in force; a new screen follows them and `tools/a11y/check.py` finds what slipped.

- **48 dp.** A thing that is tapped is at least 48 dp each way to a screen reader and a finger. `Modifier.minTouch()` grows the thing itself (use it where there is room); `Modifier.reach()` lays a 48 dp area over a smaller thing that must keep its size in the layout (`size(32.dp).reach()`), as the template card's menu, the swatches and the variation cross do. - **Names and roles.** An icon that is the only label of a control has a content description; an icon beside text has none. A control says what it is: the set's tick is a checkbox ("Set 2", done / not done), the weight and reps boxes read "Set 2 weight, 80 kilograms", the set number reads "Set 2, warm-up. Change type", a `Toggle` row is one switch, a colour swatch is a radio button named for its colour, PR badges say "Reps, matched" or "1RM, new PR". ## Presets and the Look

A look is a preset (`theme.preset`: `light`, `dark`, `amoled`, `mono`, `linen`; AMOLED is the app's own look and the default) with optional parts swapped (`theme.mix.<part>` = a value id) and the older single options as overrides (`accent`, `palette`, `background`, `theme` for Dark / Light / System). `resolveLook` (`ui/theme/Presets.kt`) turns them into one immutable `Look`; `AppModel.look` is that, and `CleanTheme(look, ...)` builds the Material scheme from it (`Look.colorScheme()`) and provides `LocalLook`. With AMOLED and no mixes the scheme is exactly the one built before presets. The parts and their values are the table in `docs/customization.md`, section 1. A screen types no colour or corner of its own for these: cards (`Section`) read the fill, transparent (AMOLED's since 2026-10-15: no fill, the 1 dp outline alone), see-through or solid, the outline and the soft shadow; the Today card the tint; buttons the round or card corner (`buttonShape()`); the tab bar the black or matching style; area shading under chart lines the fill opacity; the calendar and body figure the colour scale (`AppModel.palette`, which is the user's palette when one is chosen, else the preset's); `Motion.speed` shortens every tween by the look's factor (never the rest's clock). A card colour only fits its mode (solid white on a light look, solid slate on a dark one); any other mix falls back to the see-through card. `AppModel.choosePreset(id)` sets the preset and clears every mix and override.

Appearance page (step 1b): top to bottom Preset chips, the Mono panel (only on paper; directly under the presets since 2026-10-16), the Day & night panel (only with that chip), Mix and match, then the rest: Home, Tab bar, Charts, Customize. Every dropdown row is 48 dp tall and speaks as "Part: value"; since 2026-10-16 there is no separate Colours card: Mix and match's Accent row lists the presets' accents, then the named accents and "Your own colour…" (the wheel), Colour scale the presets' ramps, then the named palettes and your own, and an Icon accent row follows App icon (Preset's own, the accents, Ink); a named or own colour is stored in the old override keys (`accent`, `palette`, `theme.iconAccent`), which still win over `theme.mix.*`, and picking a preset's value clears the override; rows show small swatches; a part with one distinct value across the presets is shown disabled. Saved presets and reset (2026-10-16): under the six chips a "Custom" sub-heading holds the looks the user saved as chips (the first four, then a "Show more" chip that opens them all and becomes "Show less"); a hold on one opens Rename and Delete (delete says so with an Undo). ### Mono (step 2)

No hue anywhere (2026-10-16). While the look is on paper (`Look.mono`, which includes Mono chosen under Day & night), every colour is a grey, built in the one place the look is made rather than screen by screen: the accent is the ink whatever accent was chosen, the colour scale is `monoScale` (paper to ink) whatever palette was chosen, the Material scheme's tertiary and error roles are the ink at a strength (so the matched badge, the favourite star and every delete are grey), and the meaning colours (`monoMeaning` in `Theme.kt`) are greys of different lightness on the paper-to-ink ramp: ready lightest, then recovering, then fatigued darkest; a ticked set / PR darker than a warm-up or matched; failure and drop between; danger and the full-strength colour are the ink. Because everything that meant something by colour reads these (the body figure in every view and `BodyMini`, the summary figure and its legend, the fatigue and strength legends, PR badges, set-type colours, BMI bands, the calendar shading, charts, the ring, buttons, switches, the tab pill, snackbars), they follow without a change of their own. The chart lines of the "All" chart are four greys of different lightness (`seriesColors()`), template colours are the ink at ten strengths, sticky note bands go through `Color.inLook()` (the grey of the same lightness, `toGrey()`, which takes the luminance with the usual weights and keeps alpha). Negative inverts the grey result as before. Exceptions that still show hue: the colour wheel and the swatches of accents and palettes on the Appearance page (they are the controls for colours Mono does not use), the widgets and the launcher icon (outside the app's own screens), and the ink's own faint cool tint (`#16181D` at the slider's zero).

Card border (2026-10-17, round 10, the user's note "Card border"). The control already exists: Mix and match's **Outlines** part (kv `theme.mix.outlines`, a basic part), None / Thin (1 dp, the scheme's `outlineVariant` at 60 %) / Ink (1.5 dp, the text colour) / Hairline (1 dp `#E6E3DD`, which also becomes the row divider), each preset's own value first (Light and Dark none, AMOLED thin, Mono ink, Linen hairline); it is saved in a saved look, cleared by Reset to preset and previewed live like any part, and no second control was added. Every card reads it through `cardBorder()`: `Section`, `Tile`, the Progress mini pages, the share card, and since round 10 the page growing out of a card (`cardTarget` draws the same outline while the morph runs, fading in as the card's own fades out, so the growing edge is never missing, which mattered most with AMOLED's transparent cards). Two exceptions, now limited to the preset's own look (`Look.tileOutlined()`, `Look.heroOutlineAccent()`, tested in `CardBorderTest`): Linen's grey number tiles go without the hairline only (Thin or Ink outline them too), and a tinted Today card's outline is the accent at 35 % only while the outline is the default colour (with Ink or Hairline it matches the other cards). None with Transparent cards leaves no card edge at all; that is what the two choices say.

Colour-blind safe (2026-10-16). A switch in Appearance, Mix and match (kv `theme.cbsafe` = `on`, kept when a preset is picked, part of a saved look) swaps every green-to-red meaning for Okabe-Ito blue to orange, in the one place the meaning colours are chosen (`Look.meaning()` in `Theme.kt`, from `Look.colourBlindSafe`): `MeaningDarkSafe` / `MeaningLightSafe` beside `MeaningDark` / `MeaningLight`, so no screen changes. Dark: ready and done sky `#56B4E9`, recovering `#E69F00`, fatigued and failure vermillion `#D55E00`, strength full `#F0E442`, underweight (BMI) reddish purple `#CC79A7` so it stays apart from healthy. Light (4.5:1 on the light scheme background `#F6F7FA`, tested): ready and done `#0072B2`, recovering `#8A6400`, fatigued and failure `#B84F00`, underweight `#A8497F`. Warm-up, drop, danger (delete) and the matched badge (amber tertiary, against the now blue PR) are unchanged. Mono ignores it (its greys carry the meaning); Negative inverts the safe set like the usual one. No screen hardcodes a meaning colour (the remaining `Color(0xFF` outside `ui/theme` are note colours, palettes and the four chart series, all the user's choices).

Mono is paper and ink. **Paper** (slider 0 to 100) goes from white to a light grey, each channel `255 - 0.4 p`; **Ink** goes from `#16181D` at 0 to a dark grey, each channel `22 + 0.62 k` above 0. Every other Mono colour is mixed from the two: quiet text is the ink at 60 % over the paper, tracks and raised surfaces the ink at 10 % (cards are the paper itself), dividers the ink at 18 %, outlines the ink at 1.5 dp, the accent the ink, and the colour scale four steps of the paper-to-ink mix (20, 45, 70, 100 %), so the calendar's and the figure's more-trained days and muscles are darker ink and an empty cell or untrained muscle is a faint ink wash. The sliders apply while the look's background part is paper (so a Mono mixed with another background ignores them). They live in kv and survive choosing a preset. **Paper texture** (default 35 %) is a fine paper grain over the whole app (multiplied onto light paper, screened onto a dark page), strength `slider x 0.55`. Since 2026-10-16 (round 7, "too block-like and repeating") it is two seamless tiles of prime sides (251 and 199 px), each at half the strength, so the pair repeats only every 251 x 199 px and no tile edge or block shows; each tile is a soft tooth (the average of three random values per pixel) over fibre-sized and larger smooth clouds (wrapped value noise with smoothstep), at about the old grain's mean darkening (`Grain.kt`); dialogs and sheets, which are separate windows, are not grained. **Numbers** are IBM Plex Mono (`TextStyle.numbers()`); a screen asks for it on a figure that is shown big or has to line up, never on prose. **Negative** turns every colour of the look (page, cards, text, accent, outline, colour scale, the Material scheme and the meaning colours) over through one function, `invertColour`. True invert (default) is `1 - c` per channel, so hues flip (orange to blue); with it off only the HSL lightness turns over and hues stay. The result is dark (status bar icons light) and the launcher icon is the black tile with the light ink.

### Exercise search (2026-10-21, the user's words: "The search is very bad")

One matcher, `searchRank` in `core/ExerciseSearch.kt` (`ExerciseSearchTest`), used by the exercise list everywhere it appears (the Exercises tab, Add exercise and Replace exercise in a workout, the template editor's picker) and by History's search for workout and exercise names (notes are still found as typed). Before it, the list kept the names that contained the whole typed text as one piece, in A to Z order, so "press incline", "isolateral" or "db lateral" found nothing.

- Every typed word must match, in any order, ignoring case, brackets, hyphens and punctuation; a word may be a whole word of the name, its start, or anywhere inside the name with the spaces taken out ("isolateral", "push down" for Pushdown).
- Shorthand and other words (`SYNONYMS`, `PHRASES`): db, bb, kb, sm, bw, ez, hs, ohp, rdl, sldl, bp, lp, cg, wg, inc, dec, ext, tri / tris / tricep, bi / bis / bicep, lat (lateral or lats), pec / pecs (chest), delt(s), quad, ham(s), glute, calf, ab, "pec deck" (Chest Fly (Machine), butterfly), "skull crusher", "military press"; a plural finds the singular.
- A word of four letters or more may be one edit off (two from eight letters), as a whole word or as the start of one; shorter words must be exact.
- A word not in the name may be in the exercise's other names (`otherNames`), then its main muscles and its equipment filter word.
- Order: the name itself, then names that start with what was typed, then every word whole or as a word's start, then inside the name, then other names, then slips, then muscles or equipment; ties go to the exercise done most often, then most recently, then A to Z. While something is typed the list is that one ranked list, without Favourites, Recent or letter headings; with the box empty it is as before. "Create …" is offered as before.
- Speed (2026-10-22, the user's words: "Search is very laggy and slow"). The list used to be ranked in composition on the main thread, reading the query again for every exercise and allocating a table per typo check: 3.4 ms per keystroke over the 1605 built-in exercises on the PC's JVM, several times that on a phone, with every keystroke waiting for it. Now each exercise's words are read once per list (`SearchTarget`, built off the main thread), the query once per keystroke (`SearchQuery`, which also holds the typo check's rows and stops a check once it cannot come under the limit, and tries the other names before any slip), and the list is made on `Dispatchers.Default` with the newest keystroke cancelling the older search; the previous list stays on screen until the new one is ready, and "Create …" waits for the search it depends on. 0.73 ms per keystroke (`ExerciseSearchSpeedTest`, budget 1.5 ms). History's search reads the query once and matches off the main thread the same way.

decimals. No estimate is shown beside a warm-up. A tile's trend line stops at the last finished week or month (`finished()`). A day in a

differs from the row's. Proposals still open are in `docs/uiux-pass.md`.

### Correcting a finished workout (2026-11-02, the user's words: "it should be a different system to correct exercises, and you should be able to edit the start and end times")

Edit on a finished workout's page opens the **Correct** page (`CorrectScreen` in `Active.kt`), not the workout screen: a page with the usual back bar titled "Correct workout" and a Save button. Under it the workout's name (typed in place), its note, **Start** and **End** (each opens the phone's date and time pickers; moving the start keeps the end, so the length follows) and **Duration**; with the end not after the start, Duration is replaced by a red line and Save is greyed. Then the workout's cards, as in a workout (same set rows, number pad, set types, RPE, notes, add or remove sets and exercises, the card menu's Move up and down), with no tick boxes: every set that holds its values counts when saved, an empty one is left out. There is no clock, rest timer, focus mode, PR celebration, banner or notification, and it is apart from the workout in progress (`AppModel.correction`, a second draft): one may run while another is corrected. Save replaces the stored workout in one transaction (`Repo.correctWorkout`) and everything derived follows; Back with no change leaves at once, with changes it asks "Discard changes?". A correction left in the workout in progress by a version before this one moves to the Correct page at start-up.


## What's new (2026-11-16, the user's design)
Once after an update, the newest version's changes show as a card in the middle of the screen with the app dimmed behind it: the title "What's new in <version>", a close button, one change per page to swipe through and dots for where you are (`WhatsNew.kt`, `WhatsNewPopup`). Back or a tap outside also closes it. Only the newest version is shown; every version is listed under Settings, Credits, beside the Source code link. The text is `app/src/main/assets/changes.md` (one `## <versionName>` section per version, one `- Title: sentence` line per change; add the section before a release). The rule is `whatsNewDue` in `core/WhatsNew.kt` (`WhatsNewTest`): shown when the running versionName has a section and kv `whatsnew.seen` (the last version shown) differs; a first run (the welcome questionnaire is due) records the version as seen and shows nothing.
